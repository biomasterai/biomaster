BIOMASTER 2.0 / GETTING STARTED.

Install. Launch. Connect your model.

A practical first-run guide for the desktop app and WebUI. Bring your own LLM API key; BioMaster does not require you to send that key to a BioMaster cloud service.

1. Get the right package

BioMaster 2.0.0-beta.1 has separate desktop and WebUI packages for macOS Apple silicon, macOS Intel, and Ubuntu x64. Windows is not part of this release. Use the platform-specific download links or the official release page, and compare downloaded files with its SHA-256 checksums.

macOS desktop

Choose the mac-arm64.dmg package for Apple silicon or mac-x64.dmg for Intel. Open the DMG, drag BioMaster.app to Applications, then open BioMaster. Keep any older user data until you have chosen whether to import it. The Intel beta is unsigned; macOS may block its first launch. If you trust the verified GitHub download, use Finder's Control-click → Open flow. Neither macOS package is advertised as notarized.

Ubuntu desktop

Choose the linux-amd64.deb package and install it with the graphical package installer, or from its download directory:

sudo apt install ./biomaster-2.0.0-beta.1-linux-amd64.deb

An AppImage is also available on the release page; make it executable before opening it.

WebUI — browser or remote server

Choose the biomaster-web archive for the computer or server where it will run, then extract it. The interface opens in your browser and is backed by a service on that host—not a BioMaster cloud account. Keep the included biomaster, biomaster-mcp-runtime, and uv files together.

2. Launch BioMaster

For the desktop version, open BioMaster from Applications or the Ubuntu app menu. On first launch, complete the brief installation registration. If BioMaster finds earlier local data, choose whether to import it before continuing.

For WebUI on your own computer, open a terminal inside the extracted package directory and run:

./biomaster web

BioMaster opens the interface in your default browser. Leave the terminal running while you use it; press Ctrl+C to stop the service. The packaged WebUI includes its runtime tools, so you do not need to install Node.js, Bun, uv, or Python merely to launch it. Notebook Python packages and SmartFlow's Java/Nextflow runtime are separate needs when you use those features.

For a remote server, keep BioMaster bound to localhost and use an SSH tunnel rather than exposing its port directly to the internet. On the server, run ./biomaster web --hostname 127.0.0.1 --port 4096 --no-open. On your computer, run ssh -L 4096:127.0.0.1:4096 user@your-server, then open http://127.0.0.1:4096 in your browser. Replace the host and username with your own; choose another local port if 4096 is occupied. Your project files and API credentials reside on the server in this setup, so use a server you trust.

3. Connect an LLM API in the interface

BioMaster uses your provider account and API key. The easiest route is Settings → Providers. Connect a listed provider, or choose Custom provider when your service exposes an OpenAI-compatible or Anthropic-compatible API.

  1. Select the compatible protocol the provider documents. Enter a short provider ID and display name.
  2. Paste the provider's base URL and API key. Enter the exact model ID accepted by that API, not only its marketing name.
  3. Save, then use Settings → Models to make the model available if needed. Select it in a Chat task and send a small test request.
Example, OpenAI-compatible lab gateway
Protocol: OpenAI-compatible
Provider ID: my-lab
Base URL: https://llm.example.org/v1
Model ID: lab-chat
API key: the key issued by that gateway

The hostname and model above are examples, not a live service. Replace them with the exact values from your provider. A 401 usually means the key or authentication format is wrong; a 403 can mean model access, account permissions, or endpoint policy—not necessarily a bad key. Verify the same URL and model with the provider before changing BioMaster settings.

4. Or edit the config file directly

Yes—this is supported. BioMaster reads a JSONC configuration file; the UI's Advanced provider editor is another way to enter provider configuration. For the desktop app, use Settings → General → Open data directory, then open config/biomaster.jsonc. In the standalone WebUI, the default is ~/.config/biomaster/biomaster.jsonc unless BIOMASTER_CONFIG_HOME changes the directory.

The on-disk format has a top-level provider object. This complete example defines one OpenAI-compatible provider and one model:

{
  "$schema": "https://biomaster.nucleome.ai/config.json",
  "provider": {
    "my-lab": {
      "name": "My Lab",
      "npm": "@ai-sdk/openai-compatible",
      "options": {
        "baseURL": "https://llm.example.org/v1",
        "apiKey": "{file:./my-lab-key.txt}"
      },
      "models": {
        "lab-chat": { "name": "Lab Chat" }
      }
    }
  }
}

Replace the example URL and model ID. Put your actual key as the only line in my-lab-key.txt beside the JSONC file, with access limited to your user; {file:...} reads it without embedding the secret in JSONC. Alternatively, omit apiKey here and enter the key through the provider UI; BioMaster stores UI-entered credentials separately in its local data directory. For an Anthropic-compatible endpoint, use @ai-sdk/anthropic and the URL/model ID documented by that provider.

After editing, restart BioMaster, check that your model appears in Settings → Models, and send a test prompt. Back up your config before manual edits. A malformed JSONC file or a missing key file can prevent that provider from loading.

5. Try one Chat project

Choose New project → Chat, name the project, and confirm its directory. Create a task, select the configured model, and try: “List the files in this project and tell me which one you would inspect first. Do not change them.” You can switch to Notebook or Team by creating a separate project of that type.

Explore the biology workbenches

BioMaster lists specialist workbenches under Plugins. Choose Open workbench, then select an existing Chat project or create a new Chat project. Notebook and Team projects are not compatible with this action.

  • Motif: work with sequences, molecular designs, and Sanger traces.
  • JBrowse 2: browse a reference genome with annotation, alignment, variant, and quantitative tracks.
  • Gosling: create linked genomic visualizations with a reusable specification.
  • SmartFlow: review, authorize, and monitor registered Nextflow workflows. To execute a workflow, set up the required Nextflow and Java runtime on the computer first.

Use your own relevant files and verify the reference assembly, source data, and outputs before interpreting results. See actual workbench screenshots from demo projects.

What to try next

Chat: Give the agent a goal, data location, constraints, and the output you want; inspect its proposed plan and results.

Notebook: Combine Markdown, Python, Bash, and Prompt cells. The Files tab shows your project files. Python packages belong to the selected Notebook environment.

Team: Use issues, delegated work, and review when one project has several independently checkable deliverables.

Cite the original research

The Patterns paper describes BioMaster 1.0, the original multi-agent bioinformatics system. This website and guide describe BioMaster 2.0, the subsequent workbench.

When reporting research, state the actual BioMaster version, model, configuration, and workflow you used. Cite the original paper for its research contribution; its published experiments evaluate version 1.0.
